# Math Self-Learn 教學設計憲章

## 1. North Star

這個網站的目標不是「涵蓋最多數學」，而是讓學習者在腦中長出一個能操作、能預測、能遷移的模型。

我們追求接近 3Blue1Brown 的精神：

- 先讓人看見結構，再替結構命名。
- 先產生「原來如此」，再進入「如何計算」。
- 讓圖像與動畫承擔推理，不只負責裝飾。
- 公式是被壓縮過的 insight，不是課程的起點。

這不是要求模仿 3B1B 的視覺外觀。真正要借用的是它的教學觀：用精心安排的視覺變化，讓抽象關係變成可感知的因果。

## 2. 學習者與語言

- 預設讀者是好奇、願意思考，但尚未熟悉本主題的自學者。
- 不預設讀者已懂術語；若有先備知識，課程入口要明說並提供回顧入口。
- 主文使用自然、精準的繁體中文，但不追求把所有數學術語硬翻成中文。
- 定理、概念、方法與重要物件第一次出現時，原則上要同時標註常用英文，例如「條件機率（conditional probability）」與「中央極限定理（Central Limit Theorem, CLT）」。
- 首次介紹後，選擇該領域實際最常使用、最利於搜尋與閱讀教材的稱呼，並在同一章內保持一致；不必每次重複中英並列。
- 若繁中譯名罕用、彆扭、有多種譯法或反而增加理解成本，可以直接使用英文，不必顯示繁中譯名。例如 likelihood、Jacobian、SVD、bias–variance tradeoff 等詞應依目標讀者與上下文判斷。
- 符號第一次出現時也要把英文讀法與語意接起來，例如「\(P(A\mid B)\)：A given B，也就是已知 B 時 A 的機率」。
- 英文標註的目的，是讓學習者能銜接原文教材、搜尋資料並建立術語辨識；不是把每句話寫成中英對照，也不要堆疊括號打斷敘事。
- 語氣像一位很會畫圖、願意陪學生試錯的老師，不像論文、規格書或補習班公式講義。
- 不用「顯然」「不難看出」跳過真正困難的認知步驟。

### 顯示環境

- 本專案目前是 desktop-first，主要驗收環境為一般電腦與約 1920×1080 的螢幕比例。
- 不要求為手機、平板、觸控操作或窄螢幕另外設計 RWD 版本。
- 不要為未使用的 mobile breakpoint 花費設計與實作時間；優先把桌面上的視覺敘事、資訊密度與互動品質做好。
- 基本的視窗縮放不應讓內容完全無法操作，但這不等同於需要完整的 mobile layout。

## 3. 每個小節的核心單位：一個 insight

開始實作前，先寫出這句內部設計句：

> 學完這一小節，學習者應該能直覺地看見／預測＿＿＿＿。

如果一句話填不完，通常代表小節需要拆開。每個小節建議依下列節奏設計，但不必機械地套版：

1. **衝突或問題**：一個會勾起直覺、最好還能讓人猜錯的具體情境。
2. **先預測**：讓學習者在看到答案前做選擇、拖曳、估計或畫出預期。
3. **可操作模型**：用最少控制項呈現關鍵變數，操作後立即得到有意義的回饋。
4. **引導注意**：動畫、標註或狀態切換只凸顯此刻要觀察的關係。
5. **壓縮成觀念圖卡**：用一張短而強的圖卡留下可攜帶的 mental model。
6. **遷移**：換一個表面不同、結構相同的例子，確認理解不是只會照著玩。
7. **選修深挖**：符號、正式定義、推導、證明與邊界案例放進可展開區。

主流程應該在隱藏所有「深挖」內容後仍然完整、正確、可學。

## 4. 內容分層

### 主流程：直覺與判斷

主流程優先回答：

- 這個概念為什麼需要存在？
- 哪個量在變？哪個關係保持不變？
- 我改動一件事，接下來應該發生什麼？
- 這和前一個概念如何接上？
- 最容易產生的錯誤直覺是什麼？

主流程可以有公式，但必須是觀察後的命名或壓縮，不能是無動機的第一幕。

### 次要流程：正式化

以下內容預設放在「展開推導」「符號說明」「為什麼成立」「嚴格版本」等可展開區：

- 完整符號表
- 公理化定義
- 定理的所有條件
- 代數推導
- 正式證明
- 技術性反例與例外

「藏起來」不等於可以不嚴謹。展開內容仍須正確、完整，且要說清楚它和主流程的直覺如何對應。

### 關鍵觀念圖卡

每個重要小節至少留下一個視覺上突出的核心句或關係圖。好圖卡應該：

- 離開上下文仍大致看得懂。
- 通常只有一個主要訊息。
- 配一個小圖、狀態對比或空間關係，而不是純色文字框。
- 說的是可遷移的模型，不只是本題答案。

例如機率課應留下：

> 機率不是預言；它是在資訊不完整時，替可能世界分配重量。

以及：

> 條件機率：世界縮小。獨立：縮小後比例不變。互斥：兩個事件沒有重疊。

## 5. 視覺不是插圖，而是推理介面

在寫長段落以前，先問能否用以下方式表達：

- 空間中的位置、面積、長度或重量
- 同一物件的 before / after
- 兩個同步視圖之間的對應
- 一個參數變化時，圖形如何連續變形
- 多次試驗累積出的軌跡或分佈
- 可拖曳、分割、堆疊、重排的物件

### 視覺語法

- 同一概念跨頁使用一致顏色；顏色代表語意，不代表「看起來熱鬧」。
- 重要元素和背景必須有清楚層級；同時競爭注意力的高亮不超過必要數量。
- 動畫應表達轉換、因果或守恆。無教學目的的漂浮、彈跳與粒子效果應刪除。
- 任何動畫都要能暫停、重播或重設；不可讓讀者因錯過時機而無法理解。
- 不以顏色作為唯一辨識方式，同時使用形狀、位置、紋理、標籤或線型。
- 數值與圖形同步變化時，要讓學習者容易看出「哪個操作造成哪個結果」。

### 何時使用 3D

不怕使用 3D，但 3D 必須解決 2D 難以表達的問題，例如：

- 曲面、旋轉、投影、基底變換或空間切片
- 多個平面／方向的相對關係
- 從不同視角觀察才會顯現的結構

若 3D 只是把 2D 圖做得更炫，會增加遮擋、透視誤判與操作負擔，應保留 2D。使用 3D 時必須提供：

- 合理的初始視角與一鍵回正
- 明確的軸、尺度或方向線索
- 限制過度自由的相機操作
- 低效能與 reduced-motion 的替代呈現

## 6. 互動設計

每個互動在動工前都要回答：

> 學習者操作什麼？預期看見什麼？這個變化證明或推翻哪個想法？

好的互動具有：

- 一個明確問題，而不是「隨便玩玩看」。
- 少量且語意清楚的控制項。
- 操作後立即、穩定、可比較的回饋。
- 預設狀態本身就能說故事，不需先閱讀操作手冊。
- 重設、重播與必要的步進控制。
- 在主要桌面環境中能以滑鼠與鍵盤完成核心探索。
- 合理的極端值與反例，讓模型邊界可被發現。

互動後要有一個短問題幫助反思，例如「你改變了哪個量？什麼沒有變？」。不要用一大段文字替使用者解讀所有觀察。

模擬隨機現象時：

- 顯示樣本數與理論基準。
- 區分單次路徑和多次實驗的分佈。
- 必要時允許重跑或使用固定 seed，避免畫面無法重現。
- 不用一次「剛好很漂亮」的隨機結果冒充定律。

## 7. 數學教學的敘事原則

- **從需要出發**：先遇到舊工具處理不了的問題，再引入新概念。
- **具體 → 結構 → 符號**：先操作例子，抽出共同關係，最後命名。
- **對比相近概念**：例如互斥 vs 獨立、結果種類 vs 結果權重，應用同一視覺並排比較。
- **刻意處理迷思**：不要只給正解；讓錯誤直覺在互動中產生可見矛盾。
- **跨表徵連結**：圖、語句、數表、公式之間要能一一指認，不只是同時擺在畫面上。
- **保持條件可見**：公平、等可能、獨立、不放回等假設不可藏在細字裡。
- **先形成判斷力，再練計算力**：練習先問「該怎麼想／哪個模型適用」，再問數值答案。

### 一般機制、特例與例子偏差

具體例子是入口，不是概念本身。選例與設計互動時，必須防止學習者把例子的偶然特徵誤認為一般結構。

#### 先分開四個層級

每個重要概念在規畫時都要明確區分：

1. **一般定義或機制**：跨不同 worlds 仍保持的結構是什麼？
2. **目前的 concrete instance**：這個例子如何讓機制可操作？
3. **特例專用 detector**：哪些判準只在特定結構成立？
4. **Course convention**：哪些是假設範圍，而不是所有教材共用的定義？

例如 unit 的一般定義是「inverse 必須存在於同一 ambient ring」；`gcd(a,n)=1` 只是 `ℤ/nℤ` 的 detector，不能視覺上呈現成 unit 的一般定義。Commutative rings 可以是課程主線，但 noncommutative 不代表「不是 ring」。

若主流程使用特例專用判準，畫面要持續顯示適用 world，例如 `CASE STUDY · ℤ/nℤ ONLY`，不能只在開頭或註腳說一次。

#### 選例前先做 accidental-property audit

採用一個主例子前，先列出它具有、但目標概念並不要求的偶然性質。若這些性質會讓一般 mechanism 看起來比實際更簡單，應換例、加入對照，或把一般模型放在例子上層。

常見風險包括：

- 所有 inverse 剛好等於自己，使學習者以為 inverse 通常不會換 element。
- Example 恰好 commutative，使 order reversal 在數值上不可見。
- 對稱參數讓兩個不同角色得到相同數值。
- 小型 finite example 中所有 samples 剛好通過，造成「抽查就是 proof」的錯覺。
- 座標、角度、距離或面積在圖中碰巧對應答案，使視覺暗示一條並不存在的一般公式。
- Ambient world 固定不變，使學習者誤以為性質只由 element 本身決定。

例子不必刻意變複雜；應選擇最小但**非退化（non-degenerate）**的例子，也就是能讓本節需要區分的角色真正產生不同可見結果。

#### 一般性檢查要改一件事、固定其他事

至少安排一次受控 transfer，以隔離 property 真正依賴什麼：

- **換 ambient world，固定 element 與 equation**：檢查性質是否依賴世界，例如 `2` 在 `ℤ` 與 `ℚ` 的 unit status。
- **換 representation，固定 mechanism**：從 number tiles 換到 functions，檢查理解是否只依賴外觀。
- **換 surface example，固定 invariant**：確認學習者能辨認同一條 two-route、conservation 或 quotient mechanism。
- **保持表面相似，破壞一項假設**：用 decisive witness 讓錯誤泛化產生可見矛盾。

Transfer 不是章末再舉一題。它必須說清楚「這次改了什麼、什麼沒改、因此證明理解依附的是哪個結構」。

#### 視覺模型也要接受語意審核

在採用 dial、距離、旋轉、面積、力、流體、容器等隱喻前，逐項詢問：

- 圖上的位置或距離真的具有數學語意，還是只是 selector？
- 動畫路徑真的代表推導過程，還是只從答案 A 飛到答案 B？
- 兩個物件畫得相同，是否會暗示它們角色相同？
- 兩個物件畫得不同，是否會掩蓋它們其實是同一 structure 的不同表示？
- 使用者能否從圖中做出一般預測，還是只能記住這張圖的外觀？

若角度、面積或空間鄰近沒有真實對應，不要用它暗示 operation。純粹用來選值的控制項應畫成 cards、ruler、buttons 或明確標示的 selector，而不是偽裝成具有推理意義的幾何。

#### Evidence 的強度必須可見

- 一個成功 example 只能展示 possibility 或 mechanism，不能證明 universal claim。
- 一個 failure witness 足以推翻 universal claim。
- 完整 finite scan 可以證明該 finite model，但不能冒充一般 theorem 的 proof。
- Simulation 支援 intuition 與估計，不取代 proof。

UI 應明示目前提供的是 `EXAMPLE`、`WITNESS`、`FINITE EXHAUSTION`、`SIMULATION` 或 `GENERAL ARGUMENT`，避免所有綠色 PASS 看起來具有相同證明力。

#### 章節的一般性最低要求

一個核心 insight 在離開規畫階段前，至少要通過：

1. 能用不綁定目前例子的語句表達。
2. 已列出主例子的 accidental properties。
3. 至少有一個 non-degenerate state，使需要區分的角色不會數值重合。
4. 特例 detector 與 course convention 都有持續可見的 scope label。
5. 至少一次 transfer 能改變 surface 或 ambient world，同時保留目標 mechanism。
6. 視覺沒有暗示不存在的幾何、順序、可逆性或因果。
7. Evidence 類型與它實際能支持的結論相符。

## 8. 文案與版面

- 一個段落通常只承擔一個意思；能用兩句講清楚就不寫六句。
- 標題應描述問題或 insight，避免全頁都是名詞型章節標籤。
- 避免連續堆疊多張外觀相同的文字卡片。
- 公式不可用普通文字拼裝；使用既有 KaTeX 元件或語意正確的數學排版。
- 不濫用粗體、彩色字、驚嘆號與全形標語。視覺強調要有固定層級。
- 充分利用桌面寬度呈現並排比較、同步視圖與空間關係，不需為手機版重新拆成單欄流程。
- 主畫面先給「下一步該看哪裡」的清楚焦點，再提供自由探索。

## 9. 練習與回饋

練習不是章末裝飾。每個核心 insight 後安排低摩擦檢查：

- 先預測再揭曉
- 拖曳配對圖與語句
- 找出哪個假設被破壞
- 比較兩個看似相同的情況
- 建造一個符合條件的反例
- 把同一結構遷移到新情境

回饋要解釋思路，不只顯示紅叉綠勾。錯誤答案若反映常見迷思，應給針對該迷思的提示。

## 10. 目前大綱的初步診斷

目前站內已有 11 個主題：

- 線性代數、抽象代數、代數幾何
- 實分析、複分析、微分方程、點集拓撲
- 機率論、數理統計、迴歸與線性模型、貝氏統計

優點是範圍完整、已累積大量 SVG／Canvas／Three.js 互動，也有章節與步驟導覽骨架。主要風險則是：

1. **廣度遠超過教學打磨深度**：不少章節像術語與成果的巡禮，尚未形成循序累積的 mental model。
2. **一小節承擔太多新概念**：例如機率第一章同時放入三種詮釋、公理、計數、生日悖論與 Monte Carlo。
3. **公式出場過早**：有些頁面先顯示正式公式，再補直覺，與本憲章的順序相反。
4. **互動存在但未必完成教學閉環**：滑桿或圖表有變化，卻未先要求預測、未凸顯 invariant，也缺少操作後的遷移問題。
5. **文字卡片偏多**：部分內容仍是「講義 + 一個 demo」，而不是由視覺逐步帶出推理。
6. **課程地圖可能重複或跳級**：線性代數、實分析、微分方程、統計之間有重疊主題，應明確標示先備關係與推薦路徑。

因此後續大修不應從統一配色開始，而應依序處理：

1. 課程依賴圖與每章 learning outcomes
2. 章內 insight 順序與拆分
3. 關鍵視覺模型與互動 storyboard
4. 主流程文案
5. 正式內容的展開層
6. 視覺 polish 與效能

### 機率課的建議重排方向

現有六章可作為知識範圍參考，但不應限制教學節奏。至少要在進入 Bayes 前，讓下列直覺各自有足夠空間：

1. 機率在描述不確定性，不保證短期結果
2. 完整結果、樣本空間與事件的層級
3. 結果種類不等於結果權重；等可能是假設
4. 加法與乘法其實在描述「分支合併」和「連續選擇」
5. 補事件與「至少一次」的反面思考
6. 條件機率是縮小可能世界
7. 獨立是縮小後比例不變；互斥則是沒有共同結果
8. Bayes 是在不同條件方向之間重新分配權重

章數可以增加。每頁概念變少、理解變深，比維持「六章完成」更重要。

## 11. 技術與體驗底線

- 沿用 Angular standalone components 與 signals 的既有方向。
- 優先抽出真正會重複的視覺語法、互動控制與教學容器，不為一次性畫面過度抽象。
- Three.js 場景需清理 renderer、animation frame、event listener 與資源。
- 動畫使用 `requestAnimationFrame`，並尊重 `prefers-reduced-motion`。
- SVG 要有合理的 `viewBox`、可縮放文字策略與必要的 accessible label。
- 所有互動控制要有可見 focus、可理解 label、足夠點擊區域。
- 不依靠 hover 才能取得核心資訊。
- 隨機模擬與昂貴計算不可讓主執行緒長時間卡住。
- 修改後至少執行 build/type check；涉及視覺時要以約 1920×1080 的主要桌面環境實際檢查。

## 12. 每次改課前的交付模板

在開始大改一章前，先用簡短文件或工作說明回答：

```text
核心 insight：
學習者原本可能怎麼誤解：
第一個具體問題：
一般機制如何表述：
主例子的 accidental properties：
哪個 non-degenerate state 讓角色真正分開：
主要視覺模型：
視覺可能造成的假暗示：
學習者能操作的變數：
操作時保持不變的東西：
預測 → 回饋 → 壓縮：
目前 evidence 屬於 example／witness／finite exhaustion／simulation／general argument 的哪一種：
特例 detector 與 course convention 如何持續標示 scope：
正式內容放在哪個展開層：
最後如何檢查能否遷移：
```

若這些問題無法回答，先不要進入大量 UI 實作。

## 13. 完成定義

一個小節只有在以下條件成立時才算完成：

- 有且只有一個清楚的主要 learning outcome。
- 不打開推導也能掌握核心概念。
- 視覺或互動承擔了不可被同量文字輕易取代的理解工作。
- 操作與結果之間的因果清楚，且能重設／重播。
- 公式在有需要之後才出場，假設與適用範圍清楚。
- 有至少一次預測或主動判斷，以及有解釋的回饋。
- 有一張可帶走的觀念圖卡或等價的視覺總結。
- 主例子已通過 accidental-property audit；一般機制、特例 detector 與 course convention 沒有混成同一層。
- 至少一個 non-degenerate state 讓本節要區分的角色在畫面或數值上真正分離。
- 視覺沒有用無數學語意的角度、距離、面積或動線暗示不存在的一般規律。
- Example、witness、finite exhaustion、simulation 與 general argument 的 evidence 強度沒有被混淆。
- 在主要桌面環境中可用滑鼠與鍵盤完成核心學習，低動態偏好不會遺失關鍵資訊。
- 數學正確，build/type check 通過。

最後的自問不是「內容都放進去了嗎？」，而是：

> 學習者離開這一頁後，腦中是否多了一個能拿來思考的模型？
